ℹ Data Extraction Methodology & Caveats▼

Source: 6 Excel BOQ workbooks (Civil Pkg I–III, MEI Pkg I-1/I-3/II) parsed via openpyxl with merged-cell-aware column mapping.

Unit/Zone classification: WBS column headers matched against unit name patterns (Unit 10, 10A, 20, 30, 40, 50, Zone 210, 220, 230).

Category classification: Keyword matching on item descriptions (concrete/conc/rebar/formwork → "Concrete & Civils"; structural steel/space-frame → "Structural Steel"; cable/wire/conduit → "Electrical"; transmitter/instrument/DCS → "Instrumentation & Controls"; etc.).

Known limitations:

  • BOQ quantities represent mixed units (M³, M², KG, TON, EA, LM, M, SET, LOT) — cannot be directly summed across categories
  • "Other" category captures items not matching any keyword (lump-sum rows, subtotals, provisional sums, indirects)
  • MEI Sub C combined value (AED 160.9M excl. VAT) from Subcontract Agreement Art.5; Pkg I-1 Excel total not cached — contract override applied
  • Civil Sub A individual package totals corrected (TOTA-row first-numeric, not max-numeric) to avoid double-counting combined figure
  • Some columns use merged-cell spanning across multiple WBS units — parser picks the first matched unit
  • Contract-claimed concrete volumes (42,271/28,158/8,092 m³) may include provisional allowances not yet in BOQ
