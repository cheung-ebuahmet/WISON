这个数据库是什么、为什么存在

目标：理解数据库的定位、结构与覆盖范围。
这是一个把全部分包 BOQ 单价"集中成 CSV"的查询库——查价比价不用再翻 Excel。

它解决什么问题

原始价格表散落在 D:\Wison\Subcon_Payments\ 各分包合同目录下，都是 Excel，格式不一。每次想对比两家分包商同一个项的报价，得手动开好几个 Excel 翻表。

这个数据库把每个 Excel 的每个工作表转成一个 CSV，集中放在 D:\Wison\_tools\price-database\，配一个 _query.py 查询脚本，做到"一句命令搜全库"。

一张 CSV 的"六要素"列公式

目标：看懂定价表那串 a/b/c/d/e/f 列到底在算什么。
每个可计量项的成本 = 人工(b) + 材料(c) + 工器具(d) + 机械(e)，四要素加总得直接成本 f。

这是全库最核心、也最容易被搞混的地方。所有定价表（无论土建还是 MEI）都用同一套六列公式，但列号因文件不同而异（所以才有 _column-mapping.md 这份对照表）。

通用六列公式（按语义，不按列号）
代码含义是否计入总价说明
aManhours U/Rate（工时单价）❌ 不计入参考值，单独列，不参与 f 的求和
bLabor Cost U/Rate（人工）✅ 计入人工单价
cMaterial Cost U/Rate（材料）✅ 计入材料单价
dTools & Consumable U/Rate（工器具）✅ 计入工具/消耗品单价
eEquipment Cost U/Rate（机械）✅ 计入机械单价
fDIRECT COST TOTAL U/Rate✅ 合计f = b + c + d + e
两个最易犯的错：
① a（工时单价）不计入 f——很多人直觉以为 f 包含 a，其实 a 只是给你看"要多少工时"的参考列。
② U/Rate 和 Amount 是两回事——U/Rate 是单价，Amount = Qty × U/Rate 是金额。查单价要看 U/Rate，别拿 Amount 当单价。

为什么"列号因文件而异"

因为不同合同包的列数不一样（土建有 WBS 分区列、MEI 有 TAG 号列），导致 a/b/c/d/e/f 落在不同列。举例（土建 CIVIL Green）：

内容CCECC Pkg IITCC Pkg ITCC Pkg III
Material U/Rate (c)C19C19C18
DIRECT COST TOTAL (f)C25C25C24

所以别死记列号，要看 _column-mapping.md 或按表头文字定位。

用 _query.py 查：list / cat / 关键词

目标：掌握三个查询命令，一句命令搜全库。
三个命令：--list 看清单，--cat 按分类精确搜，关键词全文搜。

命令一：列出所有工作表

# 看库里有哪些表、每个表多少行
cd D:\Wison\_tools\price-database
python _query.py --list

命令二：按关键词全文搜索

# 搜所有 CSV 里包含 DUCT BANK 的行
python _query.py "DUCT BANK"

# 多个关键词 = 同时满足（AND）
python _query.py "MANHOLE" "CONCRETE"

命令三：按 Category 精确搜

# 只看 Category 列 = MANHOLE 的行（不是全文模糊匹配）
python _query.py --cat MANHOLE
什么时候用哪个：
· 想快速定位"这个材料谁家报过价" → 关键词搜（如 "DUCT BANK"）
· 想按报价表的分类号精确过滤 → --cat
· 忘了库里有什么 → --list

读单价的正确姿势：U/Rate 与 f 列陷阱

目标：知道"该看哪一列"，避免把金额当单价、把工时价当总价。
查一个项的单价，看 f 列的 U/Rate；别用 Amount（金额）当单价，也别漏看 f 是四个要素的合计。

以土建 CIVIL（Brown） 里 DUCT BANK 一行（CCECC Pkg II）的真实数据为例，逐列拆开看：

列值解读

UnitM3计量单位：立方米
Qty500工程量（估算）
Manhours U/Rate (a)196.06工时参考（不计入 f）
Labor U/Rate (b)211.74人工单价
Material U/Rate (c)2,510.46材料单价（大头）
Tools U/Rate (d)200.84工器具单价

三个必须记住的读法：

  1. 看单价 = 看 f 的 U/Rate，不是看 Amount（Amount = Qty × Rate，是总金额）。
  2. f 里不含 a：工时价只是参考，别把 196.06 也算进总价。
  3. 材料(c)往往是最大头：混凝土类项材料占比通常 >80%，所以比价时重点盯 c 列差异。

跨分包商对比：DUCT BANK 案例

目标：用真实数据演示"同项比价"，并看到惊人的价差。
同一个 DUCT BANK 混凝土项，CCECC 材料价 2,510 vs TCC 466，差 5.4 倍——价差背后是范围定义不同。

把库里两家分包商同一个"DUCT BANK 混凝土"项放在一起（这是 README 里点名的经典案例）：

DUCT BANK 混凝土 (fc'=20N/mm²) · 单价对比（AED/M3）
分包商人工 b材料 c工器具 d直接成本 f
CCECC（Civil Pkg II）211.72,510.5200.8≈2,923
TCC（Civil Pkg I）1,054.1466.4159.9≈1,680
倍数5.0×5.4×0.8×1.7×

注意一个反直觉的点：两家不是"整体贵/整体便宜"，而是结构完全相反——

  • CCECC：材料贵（2,510）、人工便宜（212）→ 可能把混凝土、钢筋、模板、着色都算进"材料"了
  • TCC：材料便宜（466）、人工贵（1,054）→ 可能材料只含混凝土拌合物，人工含了模板、浇筑、养护等施工动作
所以比价绝不能只看 f 一个数字。同样的 f≈2,923 vs 1,680，看似 TCC 便宜 42%，但如果 CCECC 的"材料"里包含了 TCC 放在"人工"里的模板工程，那两家的总价差异其实是假的。必须逐要素(b/c/d/e)对齐"范围定义"再比。

识别异常：凑整 / 留空 / 倒挂

目标：练一双"扫一眼就发现数据有问题"的眼睛。
三类常见异常：金额整齐凑数（占位值）、关键项留空、费率倒挂（工头比工人便宜）。

异常一：金额"整齐凑数"（占位值）

间接费表里如果出现 268,000 / 536,000 / 804,000 / 1,206,000 / 8,040,000 这种成倍数、尾数全 0 的数字，往往不是逐项核算的真实报价，而是按某个基数比例摊出来的占位值。真实报价应该尾数参差。

异常二：关键项留空

汇总表 / 间接费表里 总部管理费、利润 这类关键行如果金额留空，是重大风险——分包可能"零利润"报价后靠变更找补，或根本漏报。

异常三：费率倒挂

正常逻辑里，工头（Foreman）费率应高于工人（Welder）。但实际数据里出现了倒挂：

同为"Welder"这个工种，四个包报出了 72 / 73 / 95.42 / 109.5 四种价，最高是最低的 1.5 倍。这可能是：① 不同项目阶段/技能要求；② 不同分包成本结构；③ 报价水分。比价时要问"为什么差这么多"。

比价前先核实"范围定义"

目标：理解"同项不同价"的根因，避免被表面价差误导。
同名的项，两家分包商报的"范围"可能完全不同——比价第一步是确认比的是不是同一个东西。

为什么"同名不同价"

以 DUCT BANK 为例，一个"CABLE TRENCH 混凝土"背后可能包含完全不同的工作内容组合：

  • 是否含开挖/回填（excavation/backfill）？
  • 是否含模板（formwork）？
  • 是否含钢筋（rebar）？
  • 是否含着色涂层（红/绿氧化色标）？
  • 混凝土是分包自购还是总包供料（free issue）？

每一项"含/不含"都会把价格推高或压低，甚至改变"材料"和"人工"的归属。这解释了第 6 课看到的人工/材料结构倒置。

怎么核实范围定义

  1. 看 BOQ 项的描述全文（Description 列往往很长，含规范引用如 BS EN 12878）
  2. 对照 Responsibility Matrix（谁供料、谁施工）
  3. 对照 Method of Measurement（怎么计量）
  4. 看 Material Supplied By 列（MEI 表有，标 Contractor 还是 Subcontractor）
经验法则：跨分包商比价时，先比"范围"再比"价"。范围一致才谈得上比价；范围不一致，价格差异没有可比意义。

用到实战：变更计价 / 定价基准 / 谈判

目标：把数据库从"能查"变成"能赚钱/能省钱"的工具。
三个实战用途：变更算新价、新标定价基准、谈判压价抓手。

用途一：变更计价（引用现成费率）

现场发生变更、点工、待工时，直接用库里的费率表算钱，而不是临时谈价：

  • Labor Rates：点工按 AED/hr（含加班价）
  • Equipment Rates：机械按月租/日租/待机三档
  • 拆除价：合同约定拆除 = 安装单价的 30%（可查对应安装项 f 列）

用途二：新标定价基准

下次招标定"合理价区间"时，拉出库里同类项的多家历史报价做基准：取中位数、看离散度、识别谁报得离谱高或离谱低。

用途三：谈判压价 / 对账抓手

  • 分包报了个新项价格，你可以用库里其他分包商的同类项压价："同样 DUCT BANK，别人材料才 466，你报 2,510，解释一下范围差在哪。"
  • 对账时发现某分包某要素（如材料 c）异常高，可要求对方拆出构成。
一句话总结整个数据库的价值：它是你的"分包价格记忆"。有了它，任何比价、定价、谈判都不用凭印象，直接查历史数据说话。
